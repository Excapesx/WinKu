# 重做计划 v1

前提（已定）：不上架、自用+分享；界面重做；多服务商；内核用 dsh。

---

## 1. 定位

一台手机上的 agent 助手。**聊天是主场，动手是杀手锏。**

不做的事：不做第二个"聊天框 App"，也不做第二个"手机自动化工具"。两者必须合成一个东西——一个用起来像 ChatGPT、但真的能替你办事的 App。

自用 + 分享意味着：不用为应用商店的合规做妥协，可以做得很强；但也不能靠"功能多"取胜，因为分享出去以后没人会读说明书。

---

## 2. 信息架构：三个屏

```
┌─────────────┐   ┌─────────────┐   ┌─────────────┐
│   对话       │   │  会话抽屉    │   │   设置       │
│  （唯一主场） │   │  历史/搜索   │   │  模型/权限   │
└─────────────┘   └─────────────┘   └─────────────┘
```

**对话**：消息流、输入框、附件、模型切换、权限模式。工具调用折叠成一行，重要的结果升成卡片。

**会话抽屉**：新建、历史、搜索。不做多标签、不做项目分组（v1）。

**设置**：模型服务（多服务商）、手机权限、自动化（收进"高级"）。轨迹视图放进长按菜单，不做独立入口。

砍掉的入口：扩展市场、学习页、磁贴、输入法、系统助手。功能可以留着，入口一律不给。

---

## 3. 视觉

重做，不复用现在照 dsh Web 抄的那套 token。

方向沿用「冷铸」并做暖化处理：中性色做骨架，一个主色承担全部动作语义，内容区（代码、图表、产物）才有彩色。要解决的三个具体问题：

1. **深色是一等公民**，不是反相。手机上大部分时间在暗环境。
2. **字号只有五档**，行高固定 1.6–1.8，中文优先。
3. **动效只做三件事**：流式文字、卡片展开、面板推入。其余一概不做。

验收：截图去掉颜色后，层次依然清楚。

---

## 4. 引擎侧五件事

| # | 问题 | 做法 | 验收 |
|---|---|---|---|
| 1 | 冷启动 5 秒 | 进前台就预热引擎；工具清单与提示词延迟到首次发送；首字前不做非必要初始化 | 点发送到首字 < 1.5 s |
| 2 | 会话会丢 | 发送队列 + 幂等键；进程被杀后按事件序号续传；错误可重试且不重复 | 飞行模式切换 20 次，消息不丢不重 |
| 3 | 多服务商配置散 | 服务商配置收敛到一个 ProviderRegistry，设置页只有一处入口；密钥仍走 Keystore | 加一个自定义 OpenAI 兼容服务 < 30 s |
| 4 | 补丁栈难维护 | 每个补丁标注"为何必须、能否进插件"；能进插件的一律迁走；每次升 dsh 重审一遍 | 补丁数从 21 降到 10 以内 |
| 5 | 审批太吓人 | 三档权限保留，默认档位改成"询问"；审批从居中弹窗改成输入框上方的一行卡片 | 首次使用不会一上来就被弹窗拦住 |

## 5. 里程碑

**M1 地基（做完才能动界面）**
git 基线、可复现构建、崩溃与 ANR 上报、冷启动测量脚本。
验收：真机连续用一周不崩；冷启动有数字可对比。

**M2 外壳**
设计系统 + 对话页 + 输入框 + 流式 + 附件 + 模型切换。
验收：没用过的人 30 秒内发出第一条消息并看懂回复。

**M3 工具面**
工具行折叠、审批卡片、artifact 卡片、失败与重试态。
验收：一次完整的"查资料 → 生成表格 → 导出"能走完。

**M4 多模态**
拍照/相册进模型、语音输入、文件（PDF/Word/Excel）抽取。
验收：拍一张白板，能直接转成结构化内容。

**M5 打磨**
空状态、错误文案、深色、键盘与滚动、触感。
验收：连续用三天，没有一次想卸载。

---

## 6. v1 不做

- 多会话并行跑（同一时间只跑一个会话）
- 项目/知识库/记忆（先靠会话历史）
- 自动化规则的可视化编辑（保留引擎能力，界面不做）
- 任何形式的账号体系（分享出去也是各用各的 key）
- 平板与大屏适配

---

## 7. 风险

1. **构建链重**：JDK 21 + compileSdk 37.2 + NDK r29 + 预编译 libnode + engine.zip。任何一环断，整个项目停摆，所以 M1 必须先做可复现构建。
2. **dsh 升级**：补丁栈和引擎包绑定，升一次要重编重测。先接受"半年升一次"的节奏，别追版本。
3. **无障碍被系统限制**：国产 ROM 会杀后台、限制后台启动。自用场景可以手动加白名单，分享时要在设置里写清楚。
4. **模型能力差异**：多服务商意味着同一个提示词在不同模型上效果不同。用会话模式把"手机操作"和"纯聊天"分开，避免一个提示词打天下。
